What is Acai?

Acai is a lightweight frontend framework built to eliminate repetitive project setup and help developers start building responsive websites faster.

Most frontend projects begin with the same work: creating folders, configuring Sass, connecting JavaScript, organizing reusable HTML, setting up build tools, and preparing files for deployment. Acai brings those pieces together into one reusable starting architecture.

Why Acai Exists

Acai exists so developers can spend less time rebuilding project foundations and more time designing, coding, testing, and launching websites.

What Acai Provides

  • Organized HTML source files.
  • Reusable HTML partials.
  • Sass compilation.
  • JavaScript processing.
  • Asset management.
  • Automated build tasks.
  • Live development preview.
  • SEO and deployment support.

The Acai Philosophy

Acai is not designed to replace every frontend tool. It provides a flexible structure that gives developers a working foundation while allowing them to keep, replace, remove, or expand the technologies that fit their project.

How Acai Works

Acai separates the files you work on from the files you deploy.

Developers build inside the src directory. Acai then uses Gulp to process HTML, compile Sass, optimize JavaScript, move project assets, and generate the final website inside the dist directory. Gulp supports composing individual tasks into a larger workflow, which is the foundation of Acai's automated build process. :contentReference[oaicite:0]{index=0}

1. Build

Create pages, styles, scripts, images, and reusable partials inside src.

2. Process

Gulp runs the tasks configured inside Acai's build workflow.

3. Output

Processed files are placed inside the deployment-ready dist directory.

4. Deploy

Upload the generated project to GitHub Pages or another compatible hosting environment.

Build in src. Process with Acai. Deploy from dist.

Installation

Acai is designed to get you from an empty folder to a working development environment with a few commands.

Clone the framework, install the project dependencies, and start the development workflow.

Clone Acai

git clone https://github.com/crendon213wp/acai-framework

Install Dependencies

cd acai-framework
npm install

Start Development

gulp

What Happens Next?

Acai processes the project, generates the development output, starts BrowserSync, and watches the project files for changes. Gulp's watcher system is designed to run configured tasks when matching files change, while BrowserSync provides a local development server and live development tooling.

Project Architecture

Acai keeps development files organized by separating source code from generated output.

The src directory is where development happens. The dist directory contains the processed files created by the build workflow.

project/
├── src/
│   ├── partials/
│   ├── scss/
│   ├── js/
│   ├── images/
│   └── *.html
│
├── dist/
│   ├── css/
│   ├── js/
│   ├── images/
│   └── *.html
│
├── gulpfile.js
├── package.json
├── sitemap.xml
├── robots.txt
└── README.md

Source Files

This is where you write and organize the project. HTML, Sass, JavaScript, images, and partials remain separated by purpose.

Generated Output

Acai processes the source files and places the finished website inside the output directory.

Pages and Partials

Acai uses reusable HTML partials to reduce duplicated code and simplify site-wide updates.

Instead of copying the same navigation, footer, metadata, or other shared markup into every page, Acai stores reusable sections in the partials directory and inserts them during the build process.

Partial Structure

partials/
├── head/
│   ├── meta.html
│   ├── opengraph.html
│   └── twitter.html
│
├── navbar.html
└── footer.html

Include a Partial

@@include(
    'partials/navbar.html',
    {
        "active": "home"
    }
)

Why This Matters

Update a shared partial once and rebuild the project. Acai applies that change wherever the partial is included, helping keep repeated interface elements consistent.

The Acai Build Workflow

Acai uses Gulp as its build engine to automate repetitive frontend tasks.

When you run Acai, the framework executes the tasks defined inside the gulpfile.js. Gulp tasks can be composed with functions such as series() and parallel(), allowing individual processes to become one repeatable workflow. :contentReference[oaicite:2]{index=2}

HTML

Processes pages, includes reusable partials, and prepares the final HTML output.

Sass

Compiles Sass source files into browser-ready CSS.

JavaScript

Processes project scripts and prepares the output used by the finished website.

Assets

Moves project images and supporting files into the final output directory.

One command starts the workflow. The gulpfile controls what happens next.

Sass and CSS Compilation

Acai lets developers organize styles with Sass while automatically generating browser-ready CSS.

Your styles remain inside the source directory. Acai processes those files through the Sass workflow and writes the resulting CSS into the project's output directory.

Write Here

src/
└── scss/
    ├── base/
    ├── components/
    ├── utilities/
    └── application.scss

Acai Generates

dist/
└── css/
    └── application.css

Why Use This Structure?

Acai keeps styling modular. Base styles, components, utilities, and project-specific rules can be separated into smaller files while the build workflow produces the CSS file used by the website.

JavaScript Workflow

Acai gives project JavaScript a dedicated source location and processes it as part of the same automated workflow.

You can use vanilla JavaScript, add jQuery-based functionality, or adapt the JavaScript workflow to support additional libraries and project requirements.

Source

src/
└── js/
    └── application.js

Output

dist/
└── js/
    └── application.js

Keep Your Options Open

Acai does not require a specific application framework. The JavaScript workflow can remain simple for static projects or be expanded as a project becomes more interactive.

Default Technology Stack

Acai includes a practical default stack so developers can begin building immediately without choosing every tool before the first line of code is written.

These technologies are part of Acai's starting configuration. They support the framework, but they do not define what Acai must become. Developers can keep the defaults or replace them when a project requires a different approach.

Bootstrap

Provides Acai's default responsive layout and interface foundation.

jQuery

Provides an optional tool for DOM manipulation and existing plugin compatibility.

Font Awesome

Provides an icon library that can be used throughout the project.

Sass

Organizes project styling and compiles it into standard CSS.

Gulp

Automates the build workflow and coordinates project tasks.

BrowserSync

Provides Acai's local development server and browser synchronization workflow.

The Important Part

Acai is the architecture that organizes the workflow. The technology stack is the starting configuration.

Customization

Acai is designed to be changed.

The framework provides a working starting point, but it does not require developers to keep every dependency, folder, task, or default configuration forever.

You Can Keep

  • The default project structure.
  • Bootstrap.
  • jQuery.
  • Font Awesome.
  • The existing Gulp workflow.
  • The Sass architecture.

You Can Change

  • Replace CDN dependencies.
  • Add npm packages.
  • Remove unused tools.
  • Create new Gulp tasks.
  • Expand the Sass structure.
  • Add new reusable partials.

Acai Is Not a Locked System

Start with the framework as it is. Change only what your project requires. The goal is not to force every project into the same technology stack. The goal is to give every project an organized starting point.

SEO and Deployment

Acai helps organize the technical foundation of a website so the final project is easier to prepare for search engines and deployment.

Metadata can be managed through reusable head partials, structured information can be organized separately from page content, and deployment files such as sitemap.xml and robots.txt can be included in the project workflow.

Metadata

Organize page titles, descriptions, Open Graph information, and other metadata through reusable partials.

Sitemap

Generate or maintain a sitemap that helps document the public pages available on the finished website.

Robots

Include a robots file to communicate crawler guidance and reference the website's sitemap.

From Development to Deployment

Build inside src, run the Acai workflow, review the generated output, and deploy the finished dist project to your hosting environment.

Build Once. Adapt Often.

Acai gives you a reusable frontend foundation that can begin as a simple static website and evolve as your workflow, projects, and technical requirements grow.
